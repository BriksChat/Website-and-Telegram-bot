# Website and Telegram bot — LearEnglish

Учебный проект для начинающего разработчика. Репозиторий содержит всю систему целиком: автономное ядро, публикуемый сайт, REST API, базу данных, админ-панель и Telegram-бота.

Проект изучается поэтапно. На первом шаге ничего устанавливать не нужно. Каждый следующий шаг расширяет уже работающую версию.

## Что получится в итоге

```text
Сайт ──────────┐
               ├── REST API ─── общая база данных
Telegram-бот ──┘
```

Сайт и бот не копируют данные друг у друга. Они обращаются к одному API, а API сохраняет всё в одной базе. Поэтому прогресс пользователя одинаков на сайте и в Telegram.

## Структура репозитория

```text
core/                    автономное ядро без сервера и Telegram
website/                 версия сайта для работы с API и публикации
english_learning/app/    Flask API и модели базы данных
english_learning/bot/    Telegram-бот
docs/                    дополнительные инструкции
scripts/                 помощники для запуска в Windows
Dockerfile               сборка API и бота для хостинга
amvera.yml               пример конфигурации Amvera
.env.example             пример настроек без настоящих секретов
```

## Этап 1. Запустить локальное ядро

Ядро полностью автономно. В нём находятся 300 слов: 30 карточек по 10 слов. Каждая карточка проходит в два раунда по 5 пар «русский — английский».

1. На странице репозитория нажмите **Code → Download ZIP**.
2. Распакуйте архив.
3. Дважды щёлкните по `start-core.bat`.

Можно также открыть файл `core/index.html` обычным двойным щелчком.

В ядре работают:

- обучение по карточкам;
- переход между двумя раундами карточки;
- общий и личный словари;
- статистика и сложные слова;
- сохранение прогресса в браузере.

Сервер, Python, MySQL, домен и Telegram на этом этапе не нужны.

## Этап 2. Подключить локальный API и базу

Теперь данные будут храниться не в браузере, а через сервер. Для первого знакомства используется SQLite — она создаётся автоматически и не требует отдельной установки.

### Быстрая подготовка в Windows

1. Запустите `scripts/setup-backend-windows.bat`.
2. Сценарий проверит Python 3.12, при необходимости предложит установить его, создаст виртуальное окружение и установит библиотеки.
3. В корне появится локальный файл `.env`. Git его не публикует.
4. Откройте `.env` и замените значение `ADMIN_PASSWORD` на свой пароль.

Если автоматическая установка Python недоступна, установите Python 3.12 с сайта python.org, а затем снова запустите сценарий.

### Запуск API

Запустите:

```text
scripts/start-api-windows.bat
```

Не закрывайте открывшееся окно. Проверьте адрес:

```text
http://127.0.0.1:5000/api/health
```

Правильный ответ:

```json
{"status":"ok"}
```

При первом запуске API создаст локальную SQLite-базу и заполнит её 300 словами.

### Запуск сайта, подключённого к API

Не закрывая API, запустите второе окно:

```text
scripts/start-website-windows.bat
```

Откроется `http://127.0.0.1:8000`. Это уже не автономное ядро из `core`, а полная версия из `website`, которая получает данные через API.

Админ-панель находится по адресу:

```text
http://127.0.0.1:8000/admin.html
```

Для входа используется `ADMIN_PASSWORD` из файла `.env`. Через панель можно добавлять, исправлять и удалять слова общего словаря.

## Этап 3. Перейти с SQLite на MySQL

SQLite удобна для локального знакомства. Для опубликованного проекта рекомендуется MySQL.

1. Создайте базу MySQL у выбранного провайдера.
2. Откройте `.env` локально или настройки окружения на хостинге.
3. Задайте переменную:

```text
DATABASE_URL=mysql+pymysql://USER:PASSWORD@HOST:3306/DATABASE?charset=utf8mb4
```

Не вставляйте настоящий пароль в README, Python-файлы, JavaScript или GitHub. При первом подключении API автоматически создаст таблицы и заполнит общий словарь.

## Этап 4. Опубликовать API, сайт и домен

Сначала публикуется API, затем сайт.

### Переменные серверного приложения

```text
DATABASE_URL=<закрытая строка подключения MySQL>
ADMIN_PASSWORD=<надёжный пароль>
SITE_URL=https://YOUR-DOMAIN.EXAMPLE
API_URL=http://127.0.0.1:5000
CORS_ORIGINS=https://YOUR-DOMAIN.EXAMPLE
PORT=<порт, который выдаёт хостинг>
```

`Dockerfile` запускает Flask API. Если позже будет добавлен токен Telegram, в том же контейнере запустится и бот.

После публикации API проверьте:

```text
https://YOUR-API-DOMAIN.EXAMPLE/api/health
```

Затем откройте `website/config.js` и укажите свои публичные адреса:

```javascript
window.ENGLISH_API_URL = 'https://YOUR-API-DOMAIN.EXAMPLE';
window.TELEGRAM_BOT_URL = 'https://t.me/YOUR_BOT_USERNAME';
```

Загрузите содержимое папки `website` на статический хостинг и привяжите свой домен. На хостинг сайта не нужно загружать Python, Dockerfile или реквизиты базы.

## Этап 5. Создать и подключить Telegram-бота

Этот этап выполняется после публикации API.

1. Откройте в Telegram официального бота `@BotFather`.
2. Выполните команду `/newbot`.
3. Задайте имя и username нового бота.
4. Скопируйте полученный токен.
5. Добавьте токен в закрытые переменные серверного приложения:

```text
TELEGRAM_BOT_TOKEN=<секретный токен BotFather>
TELEGRAM_BOT_USERNAME=<username без символа @>
SITE_URL=https://YOUR-DOMAIN.EXAMPLE
API_URL=http://127.0.0.1:5000
```

Перезапустите приложение. Бот начнёт обращаться к тому же API и той же базе, что и сайт.

Для локальной проверки бота можно указать токен в `.env`, открыть терминал в `english_learning` и выполнить:

```powershell
.venv\Scripts\activate
python -m bot.launch_bot
```

Никогда не отправляйте `.env` в GitHub и не показывайте токен на скриншотах.

## Как работает синхронизация

У каждого пользователя есть `Chat_ID`. Сайт и бот передают его API:

```text
Ответ на сайте → API → база данных
Ответ в боте  → API → та же база данных
```

Если на сайте указан тот же `Chat_ID`, что выдал Telegram-бот, прогресс становится общим.
