<h1 align="center">LearEnglish</h1>

<p align="center">
  Учебный проект: автономное ядро, сайт, REST API, MySQL, админ-панель и Telegram-бот.
</p>

## Как устроен готовый проект

Сайт не подключается к MySQL напрямую. Пароли базы никогда не попадают в браузер или GitHub.

~~~text
Сайт на REG.RU ─┐
                ├─ HTTPS API в Amvera ─ MySQL в Amvera
Telegram-бот ───┘
~~~

Проходите этапы строго по порядку. После каждого этапа есть проверка. Если проверка пройдена, на этом этапе можно остановиться: уже настроенная часть продолжит работать самостоятельно.

| Этап | Результат |
|---|---|
| 1 | Автономное ядро работает на ПК без установки программ |
| 2 | Полная версия работает локально через API и SQLite |
| 3 | API и MySQL постоянно работают в Amvera |
| 4 | Сайт и админ-панель полностью работают на домене REG.RU |
| 5 | К сайту подключён Telegram-бот с общим прогрессом |

## 1. Запустить автономное ядро на ПК

Этот этап не требует Python, базы данных, регистрации или хостинга.

1. На странице GitHub нажмите **Code → Download ZIP**.
2. Распакуйте архив в обычную папку.
3. Дважды щёлкните **start-core.bat**.
4. Если Windows спросит разрешение, подтвердите запуск локального файла.

Можно также открыть **core/index.html** двойным щелчком.

### Проверка этапа 1

- открывается страница LearEnglish;
- показываются карточки со словами;
- можно составлять пары;
- после обновления страницы локальный прогресс сохраняется.

## 2. Создать свою копию и проверить полную версию локально

Для Amvera нужна собственная копия репозитория в GitHub.

1. В верхней части репозитория нажмите **Fork**.
2. Оставьте название репозитория без изменения.
3. Нажмите **Create fork**.
4. На странице своей копии нажмите **Code → Download ZIP** и распакуйте архив.
5. Запустите **scripts/setup-backend-windows.bat**.
6. Сценарий проверит Python 3.12, создаст окружение и файл **.env**.
7. Откройте **.env** и задайте собственный **ADMIN_PASSWORD**.
8. Запустите **scripts/start-api-windows.bat**.
9. Не закрывая API, запустите **scripts/start-website-windows.bat**.

Локальный сайт:

~~~text
http://127.0.0.1:8000
~~~

Локальная админ-панель:

~~~text
http://127.0.0.1:8000/admin.html
~~~

### Проверка этапа 2

Откройте:

~~~text
http://127.0.0.1:5000/api/health
~~~

Правильный ответ:

~~~json
{"status":"ok"}
~~~

Затем проверьте обучение, словарь и вход в админ-панель с паролем из **.env**.

## 3. Развернуть API и MySQL в Amvera

Подробная инструкция: [Amvera: API и MySQL](docs/infoAmvara.md).

На этом этапе Telegram-бот ещё не создаётся. Не добавляйте **TELEGRAM_BOT_TOKEN**.

В Amvera создаются:

1. отдельный проект MySQL;
2. отдельное Docker-приложение API из вашей копии GitHub;
3. секрет **DATABASE_URL**;
4. секрет **ADMIN_PASSWORD**;
5. обычные переменные **PORT=5000** и **API_URL=http://127.0.0.1:5000**;
6. публичный HTTPS-адрес API.

В репозитории уже находятся готовые **Dockerfile** и **amvera.yml**. Не создавайте их повторно через интерфейс.

### Проверка этапа 3

По публичному адресу Amvera должны открываться:

~~~text
https://ВАШ-API/api/health
https://ВАШ-API/api/all-words
~~~

Первый адрес возвращает статус **ok**, второй — карточки и 300 слов. После перезапуска API данные должны оставаться в MySQL.

## 4. Опубликовать сайт и админ-панель на REG.RU

Подробная инструкция: [REG.RU: сайт и админ-панель](docs/reg-ru.md).

Перед загрузкой сайта:

1. откройте **website/config.js** в своей копии репозитория;
2. замените локальный адрес на публичный HTTPS-адрес API Amvera;
3. оставьте **TELEGRAM_BOT_URL** пустым;
4. в Amvera укажите точные адреса сайта в **CORS_ORIGINS**;
5. загрузите содержимое папки **website** в корневую папку сайта на REG.RU.

Пример **website/config.js** на этом этапе:

~~~javascript
window.ENGLISH_API_URL = 'https://ВАШ-API.amvera.io';
window.TELEGRAM_BOT_URL = '';
~~~

Админ-панель уже входит в проект. Создавать отдельное приложение не нужно:

~~~text
https://ВАШ-ДОМЕН/admin.html
~~~

Для входа используется **ADMIN_PASSWORD**, который хранится в секретах Amvera. Пароль нельзя записывать в файлы сайта.

### Проверка этапа 4

Без Telegram-бота должны работать:

- обучение и переход между карточками;
- общий и личный словари;
- прогресс и статистика;
- добавление собственных слов;
- вход в **/admin.html**;
- добавление, изменение и удаление слов общего словаря;
- сохранение изменений после перезапуска API.

Если всё это работает, сайт полностью готов. На этом этапе можно остановиться.

## 5. Подключить Telegram-бота

Приступайте только после успешной проверки сайта и админ-панели.

Подробная инструкция: [Telegram-бот](docs/telegram-bot.md).

Кратко:

1. создайте бота через **@BotFather**;
2. добавьте токен как секрет **TELEGRAM_BOT_TOKEN** в Amvera;
3. добавьте **TELEGRAM_BOT_USERNAME** без символа @;
4. укажите адрес сайта в **SITE_URL**;
5. оставьте **API_URL=http://127.0.0.1:5000**;
6. перезапустите приложение;
7. укажите ссылку на бота в **website/config.js** и повторно загрузите этот файл на REG.RU.

После этого кнопка Telegram появится на сайте.

## Структура репозитория

| Путь | Назначение |
|---|---|
| **core/** | автономное ядро для этапа 1 |
| **english_learning/** | API и Telegram-бот |
| **website/** | сайт и админ-панель для REG.RU |
| **Dockerfile** | сборка API и бота |
| **amvera.yml** | порт и Docker-конфигурация Amvera |
| **docs/** | подробные инструкции |
| **scripts/** | локальная установка и запуск Windows |

## Безопасность

Никогда не добавляйте в GitHub, файлы сайта или скриншоты:

- файл **.env**;
- **DATABASE_URL**;
- пароли MySQL;
- **ADMIN_PASSWORD**;
- **TELEGRAM_BOT_TOKEN**;
- токены доступа GitHub.

Файл **.env.example** содержит только названия переменных и безопасные локальные значения.
