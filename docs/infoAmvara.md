# Развёртывание LearEnglish в Amvera с MySQL

Эта инструкция рассчитана на человека, который впервые пользуется облачным хостингом и базой данных. После выполнения всех шагов в Amvera будут работать два отдельных проекта:

```text
LearEnglish API (Flask)
        │
        └── внутренняя сеть Amvera ── MySQL
```

Статический сайт из папки `website` позднее можно разместить на REG.RU. На этом этапе в Amvera размещаются API и MySQL.

> Названия кнопок Amvera со временем могут немного меняться. Если точного названия нет, ищите раздел с тем же смыслом: **Проекты**, **Репозиторий**, **Переменные**, **Домены**, **Лог сборки** или **Лог приложения**.

## 1. Что уже подготовлено в репозитории

В проекте уже находятся:

- `Dockerfile` — сборка контейнера с Python 3.12;
- `amvera.yml` — запуск Docker-приложения на порту `5000`;
- `english_learning/requirements.txt` — Python-зависимости;
- `english_learning/start.sh` — запуск API через Gunicorn;
- `.env.example` — безопасный пример настроек;
- код, который при первом подключении сам создаёт таблицы и добавляет 300 слов.

Создавать таблицы вручную и выполнять SQL-команды не требуется.

## 2. Что понадобится

Подготовьте:

1. Учётную запись на [Amvera Cloud](https://cloud.amvera.ru/).
2. Репозиторий `https://github.com/BriksChat/Website-and-Telegram-bot`.
3. Отдельный пароль для MySQL.
4. Отдельный пароль для пользователя `root` MySQL.
5. Отдельный пароль для админ-панели LearEnglish.
6. Положительный баланс Amvera и подходящие тарифы.

Не используйте один пароль для разных сервисов.

## 3. Подготовьте названия

Запишите в личной заметке, которая не попадёт в GitHub:

```text
Приложение API: learenglish-api
Проект MySQL: learenglish-mysql
Имя базы: learenglish
Пользователь базы: learuser
Пароль пользователя базы: придумать самостоятельно
Пароль root: придумать другой пароль
Пароль админ-панели: придумать третий пароль
```

Для первого запуска удобнее создать длинный пароль MySQL из латинских букв и цифр длиной не менее 20 символов. Символы `@`, `:`, `/`, `?`, `#`, `&` и `%` запрещены !

## 4. Создайте MySQL

1. Откройте [проекты Amvera](https://cloud.amvera.ru/projects).
2. Нажмите **Создать** или **Создать проект**.
3. Выберите **Преднастроенное приложение из маркетплейса**.
4. Если вы запускаете проект в России, выберите в разделе **Регион** значение **Warsaw**.
5. Выберите категорию **Базы данных**.
6. Выберите **MySQL**.
7. Укажите название `learenglish-mysql` или другое понятное название.
8. Выберите тариф не ниже тарифа, на котором Amvera разрешает запуск MySQL. В документации указан тариф не ниже **Начальный**. Для резервных копий может потребоваться более высокий тариф.
9. Заполните параметры:

| Поле | Пример | Назначение |
|---|---|---|
| `MYSQL_DATABASE` | `learenglish` | База проекта |
| `MYSQL_ROOT_PASSWORD` | ваш root-пароль | Полный доступ к MySQL |
| `MYSQL_USER` | `learuser` | Пользователь API |
| `MYSQL_PASSWORD` | ваш пароль MySQL | Пароль пользователя API |

10. Нажмите **Завершить**.
11. Дождитесь статуса **Приложение запущено**.

### Важно

- Имя базы может содержать латинские буквы, цифры, `_` и `-`.
- API должен подключаться через `MYSQL_USER`, а не через `root`.
- Сохраните пароли сразу. Root-пароль может быть невозможно посмотреть или восстановить.
- Не публикуйте значения в GitHub и не показывайте их на скриншотах.

## 7. Создайте приложение API

1. Вернитесь на страницу проектов Amvera.
2. Нажмите **Создать**.
3. Выберите тип **Приложение**.
4. Назовите проект `learenglish-api`.
5. Выберите тариф.
6. Перейдите к загрузке кода.

### Подключите API к созданной MySQL

После создания приложения, но до его первого запуска, добавьте секрет подключения к базе данных:

1. Откройте проект `learenglish-api`.
2. Перейдите в раздел **Переменные**.
3. Нажмите **Добавить переменную или секрет**.
4. Выберите тип **Секрет**.
5. В поле названия укажите:

```text
DATABASE_URL
```

6. Откройте в другой вкладке проект `learenglish-mysql` → **Инфо**.
7. Найдите и скопируйте **внутреннее доменное имя** MySQL. Копируйте адрес без `https://` и без `/` в конце.
8. В поле значения секрета составьте одну строку по шаблону:

```text
mysql+pymysql://USER:PASSWORD@HOST:3306/DATABASE?charset=utf8mb4
```

Замените части строки своими значениями:

- `USER` — значение `MYSQL_USER`, которое указали при создании MySQL;
- `PASSWORD` — значение `MYSQL_PASSWORD`, которое указали при создании MySQL;
- `HOST` — внутреннее доменное имя из вкладки **Инфо**;
- `DATABASE` — значение `MYSQL_DATABASE`, которое указали при создании MySQL.

Пример с вымышленными значениями:

```text
mysql+pymysql://learuser:ExamplePassword123@mysql-learenglish-user.amvera.internal:3306/learenglish?charset=utf8mb4
```

Пароль MySQL для этого проекта должен состоять из латинских букв в верхнем и нижнем регистре и цифр. Не используйте специальные символы: `@ : / ? # & %`.

9. Вставьте готовую строку в поле значения секрета `DATABASE_URL` и сохраните его.

Настоящий `DATABASE_URL` нельзя добавлять в `.env.example`, README, папку `docs` или GitHub.

## 8. Подключите GitHub

Откройте вкладку **Репозиторий** приложения и выберите GitHub.

### Встроенное подключение

1. В GitHub откройте **Settings → Developer settings → Personal access tokens → Fine-grained tokens**.
2. Создайте токен только для `BriksChat/Website-and-Telegram-bot`.
3. Разрешите чтение содержимого репозитория. Если Amvera создаёт webhook автоматически и просит дополнительное разрешение, предоставьте управление webhook только этому репозиторию.
4. Скопируйте токен сразу после создания.
5. Вставьте токен в Amvera.
6. Выберите репозиторий `BriksChat/Website-and-Telegram-bot`.
7. Выберите ветку `main`.
8. Сохраните подключение.

Токен GitHub является секретом. Не сохраняйте его в `.env` или файлах проекта.

### Если Amvera предлагает ручной webhook

1. В Amvera придумайте секрет webhook и скопируйте предложенный URL.
2. В GitHub откройте **Repository → Settings → Webhooks → Add webhook**.
3. Вставьте URL в **Payload URL**.
4. Выберите **Content type: application/json**.
5. Вставьте тот же секрет.
6. Выберите **Just the push event**.
7. Сохраните webhook.

После этого новый `push` в `main` будет запускать обновление приложения.

### Запасной способ

Amvera также предоставляет собственный Git-репозиторий. Его можно добавить как второй remote, не заменяя GitHub `origin`:

```powershell
git remote add amvera https://git.amvera.ru/ИМЯ_ПОЛЬЗОВАТЕЛЯ/ИМЯ_ПРОЕКТА
git push amvera main:master
```

Точный адрес скопируйте из вкладки **Репозиторий** своего проекта.

## 9. Проверьте `amvera.yml`

В корне репозитория уже есть:

```yaml
meta:
  environment: docker
  toolchain:
    name: docker
    version: latest
build:
  dockerfile: Dockerfile
run:
  containerPort: 5000
```

Файл сообщает Amvera, что нужно использовать корневой `Dockerfile` и открыть порт `5000`. Не создавайте второй `amvera.yaml` через интерфейс поверх имеющегося файла.

## 10. Создайте секреты приложения

Откройте `learenglish-api` → **Переменные** → **Добавить переменную или секрет**.

Секрет хранится в защищённом хранилище. Обычная переменная предназначена для несекретных настроек.

Создайте как **секреты**:

| Название | Значение |
|---|---|
| `DATABASE_URL` | строка из раздела 6 |
| `ADMIN_PASSWORD` | отдельный пароль админ-панели |

Позже для Telegram-бота добавьте как секрет:

```text
TELEGRAM_BOT_TOKEN=токен_от_BotFather
```

Пока бот не подключается, не создавайте `TELEGRAM_BOT_TOKEN`. Тогда контейнер запустит только API.

## 11. Создайте обычные переменные

| Название | Значение |
|---|---|
| `PORT` | `5000` |
| `API_URL` | `http://127.0.0.1:5000` |
| `SITE_URL` | будущий адрес сайта, например `https://example.ru` |
| `CORS_ORIGINS` | будущий адрес сайта без `/` в конце |
| `PYTHONUNBUFFERED` | `1` |

Когда сайт появится на REG.RU, замените `example.ru` настоящим доменом. Несколько разрешённых адресов указываются через запятую:

```text
https://example.ru,https://www.example.ru
```

`API_URL` остаётся локальным, потому что Telegram-бот и API запускаются внутри одного контейнера. Браузер пользователя позднее будет обращаться к публичному HTTPS-адресу API.

После добавления или изменения переменных перезапустите приложение. Amvera применяет их после перезапуска контейнера; во время сборки они недоступны.

## 12. Запустите сборку

После подключения репозитория сборка обычно начинается автоматически. Если нет:

1. Нажмите **Пересобрать проект**.
2. Откройте **Лог сборки**.
3. Дождитесь успешной установки зависимостей и создания образа.
4. Откройте **Лог приложения**.

При нормальном запуске Gunicorn слушает `0.0.0.0:5000`. Сообщение о том, что `TELEGRAM_BOT_TOKEN` отсутствует и запускается только API, является нормальным.

При первом запуске API подключится к MySQL, создаст таблицы и добавит 300 слов.

## 13. Включите публичный HTTPS-адрес

1. Откройте **Домены** или **Настройки** проекта API.
2. Активируйте бесплатное доменное имя Amvera.
3. Выберите тип подключения **HTTPS**.
4. Укажите порт `5000`, если интерфейс запросит порт.
5. Дождитесь выпуска SSL-сертификата.

Адрес будет похож на:

```text
https://learenglish-api-ИМЯ_ПОЛЬЗОВАТЕЛЯ.amvera.io
```

Используйте адрес из своего кабинета, а не пример.

## 14. Проверьте API

Откройте:

```text
https://ВАШ-АДРЕС-AMVERA/api/health
```

Ожидаемый ответ:

```json
{"status":"ok"}
```

Затем откройте:

```text
https://ВАШ-АДРЕС-AMVERA/api/all-words
```

В ответе должны находиться карточки и 300 слов. Большой JSON-текст в браузере — нормальный результат.

## 15. Проверьте сохранение в MySQL

1. Укажите публичный адрес API в `website/config.js`.
2. Откройте админ-панель сайта.
3. Войдите с `ADMIN_PASSWORD` из Amvera.
4. Измените одно тестовое слово.
5. Перезапустите API в Amvera.
6. Снова откройте словарь.

Если изменение осталось, данные сохраняются в MySQL.

Для просмотра таблиц можно отдельно создать сервис **phpMyAdmin**, но проекту он не нужен и оплачивается отдельно. После проверки его лучше остановить.

## 16. Что нельзя отправлять в GitHub

Никогда не публикуйте:

- `.env`;
- настоящий `DATABASE_URL`;
- `MYSQL_ROOT_PASSWORD`;
- `MYSQL_PASSWORD`;
- `ADMIN_PASSWORD`;
- `TELEGRAM_BOT_TOKEN`;
- GitHub access token;
- секрет webhook.

В репозитории должен оставаться только `.env.example` с примерами. Если секрет случайно опубликован, его нужно не только удалить из файла, но и сразу заменить в соответствующем сервисе.

## 17. Частые ошибки

### `Access denied for user`

Проверьте `MYSQL_USER` и `MYSQL_PASSWORD`. В `DATABASE_URL` должен использоваться пользователь базы, а не логин Amvera.

### `Unknown database`

Имя базы в конце `DATABASE_URL` должно точно совпадать с `MYSQL_DATABASE`.

### `Can't connect`, `Connection refused` или timeout

Проверьте:

1. MySQL запущена;
2. используется внутренний домен со вкладки **Инфо**;
3. перед адресом нет `https://`;
4. порт равен `3306`;
5. API и MySQL созданы внутри Amvera.

### Ошибка разбора `DATABASE_URL`

Уберите пробелы и кавычки. Закодируйте специальные символы пароля.

### Ошибка 502

Проверьте:

- `run.containerPort` равен `5000`;
- `PORT` равен `5000`;
- домен направлен на порт `5000`;
- приложение слушает `0.0.0.0:5000`.

### API работает, но сайт не получает данные

1. В `website/config.js` должен быть публичный HTTPS-адрес API.
2. `CORS_ORIGINS` должен содержать точный адрес сайта REG.RU.
3. `http` и `https`, а также адреса с `www` и без него считаются разными источниками.
4. После изменения переменной перезапустите API.

### Новые переменные не применились

Перезапустите контейнер приложения.

### Сборка не начинается после push

Проверьте выбранную ветку `main`, состояние webhook, совпадение его секрета и срок действия GitHub-токена.
