# Amvera: API и MySQL

Эта инструкция выполняется после локальной проверки проекта. Результат этапа — работающие API и MySQL с публичным HTTPS-адресом. Сайт на REG.RU и Telegram-бот подключаются позже.

## Что уже подготовлено в репозитории

В корне вашей копии GitHub уже находятся:

- **Dockerfile** — устанавливает зависимости и запускает приложение;
- **amvera.yml** — выбирает Docker и открывает порт 5000;
- **english_learning/start.sh** — запускает API, а при наличии токена ещё и бота;
- **english_learning/requirements.txt** — Python-зависимости;
- код создания таблиц и первоначальной загрузки 300 слов.

Не создавайте второй Dockerfile или второй amvera.yml через интерфейс Amvera.

## Что понадобится

- собственный Fork репозитория в GitHub;
- аккаунт Amvera;
- отдельный пароль пользователя MySQL;
- отдельный пароль root MySQL;
- отдельный пароль админ-панели;
- положительный баланс для выбранных тарифов.

Не используйте один пароль для разных назначений.

## 1. Создайте MySQL

1. В Amvera откройте раздел проектов и нажмите **Создать**.
2. Выберите готовое приложение **MySQL**.
3. Назовите проект, например **learenglish-mysql**.
4. Выберите доступный тариф.
5. Создайте значения:

| Переменная | Пример |
|---|---|
| **MYSQL_DATABASE** | learenglish |
| **MYSQL_USER** | learuser |
| **MYSQL_PASSWORD** | собственный пароль |
| **MYSQL_ROOT_PASSWORD** | другой собственный пароль |

6. Завершите создание и дождитесь статуса работающего приложения.
7. Откройте информацию MySQL и скопируйте внутреннее доменное имя без https:// и без завершающего слеша.

Для первого учебного запуска проще использовать длинный пароль из латинских букв и цифр. Если пароль содержит специальные символы, их необходимо кодировать для URL.

## 2. Составьте DATABASE_URL

Строка подключения имеет вид:

~~~text
mysql+pymysql://USER:PASSWORD@HOST:3306/DATABASE?charset=utf8mb4
~~~

Замените:

- **USER** значением MYSQL_USER;
- **PASSWORD** значением MYSQL_PASSWORD;
- **HOST** внутренним доменным именем MySQL;
- **DATABASE** значением MYSQL_DATABASE.

Используйте пользователя базы, а не root.

Пример предназначен только для понимания формата. Настоящую строку нельзя публиковать в GitHub или отправлять на скриншотах.

## 3. Создайте приложение API

1. Создайте новый проект типа **Приложение**.
2. Назовите его, например **learenglish-api**.
3. В качестве источника выберите GitHub.
4. Разрешите Amvera доступ только к вашей копии репозитория.
5. Выберите вашу копию **Website-and-Telegram-bot**.
6. Выберите ветку **main**.
7. В качестве окружения выберите **Docker**.
8. Убедитесь, что используется корневой файл **Dockerfile**.
9. Убедитесь, что порт приложения равен **5000**.

Репозиторий уже содержит **amvera.yml**:

~~~yaml
meta:
  environment: docker
  toolchain:
    name: docker
    version: latest
build:
  dockerfile: Dockerfile
run:
  containerPort: 5000
~~~

Не добавляйте persistenceMount для этого этапа: рабочие данные находятся в отдельной MySQL.

## 4. Добавьте переменные приложения

Создайте два секрета:

| Название | Значение |
|---|---|
| **DATABASE_URL** | строка подключения из шага 2 |
| **ADMIN_PASSWORD** | отдельный надёжный пароль админ-панели |

Создайте обычные переменные:

| Название | Значение |
|---|---|
| **PORT** | 5000 |
| **API_URL** | http://127.0.0.1:5000 |
| **PYTHONUNBUFFERED** | 1 |

На этом этапе не создавайте **TELEGRAM_BOT_TOKEN**. Без него контейнер намеренно запускает только API.

Переменные **SITE_URL** и **CORS_ORIGINS** добавляются после покупки домена на этапе REG.RU. В **SITE_URL** всегда указывается один адрес сайта, например `https://example.ru`. Два адреса через запятую допустимы только в **CORS_ORIGINS**.

Секрет **DATABASE_URL** создаётся один раз. Не создавайте переменную с тем же именем повторно.

## 5. Запустите сборку

1. Сохраните проект.
2. Запустите сборку или пересборку.
3. Сначала откройте лог сборки.
4. После успешной сборки откройте лог приложения.

Нормальный запуск содержит сообщение Gunicorn о прослушивании адреса **0.0.0.0:5000**.

Сообщение о том, что **TELEGRAM_BOT_TOKEN** не задан и API запускается без бота, является нормальным на этом этапе.

## 6. Включите публичный HTTPS-адрес API

1. Откройте раздел **Домены** приложения API.
2. Нажмите **Создать доменное имя**.
3. Выберите бесплатный внешний адрес Amvera и HTTPS.
4. Дождитесь сообщения, что домен успешно добавлен.

Сохраните полученный внешний адрес без завершающего слеша, например:

~~~text
https://learenglish-api-example.amvera.tech
~~~

После создания DNS-запись появляется не мгновенно. В первые несколько минут браузер может показать `ERR_NAME_NOT_RESOLVED` («не удалось найти IP-адрес сервера»). Это не ошибка API и не требует пересборки или перезапуска приложения: подождите 3–5 минут, затем обновите страницу.

Если после появления домена адрес `/api/health` не открывается или не возвращает `{"status":"ok"}`, временно выключите VPN и обновите страницу. Некоторые VPN-сервисы не сразу видят новые DNS-записи Amvera.

Это значение потребуется для сайта на REG.RU.

## 7. Проверьте API

Откройте в браузере:

~~~text
https://ВАШ-АДРЕС-API/api/health
~~~

Правильный ответ:

~~~json
{"status":"ok"}
~~~

Затем откройте:

~~~text
https://ВАШ-АДРЕС-API/api/all-words
~~~

В ответе должны находиться карточки и 300 слов. Большой JSON-текст является нормальным результатом.

Этап завершён только после успешного открытия обоих адресов.

## Частые ошибки

### start.sh: permission denied

В актуальном Dockerfile уже выполняется:

~~~dockerfile
RUN chmod +x ./start.sh
~~~

Убедитесь, что Amvera собирает последнюю версию ветки main, затем запустите полную пересборку.

### secret-learenglish-api not found

Такого имени нет в Dockerfile, amvera.yml или коде LearEnglish. Не создавайте вручную переменную с этим названием.

Это служебная ошибка подключения проекта в Amvera. Повторно примените подключение своей ветки GitHub и запустите пересборку. Если ошибка остаётся, передайте в поддержку Amvera название проекта и системный лог.

### Access denied for user

Проверьте MYSQL_USER и MYSQL_PASSWORD. В DATABASE_URL не должен использоваться логин аккаунта Amvera.

### Unknown database

Последняя часть DATABASE_URL должна точно совпадать с MYSQL_DATABASE.

### Connection refused или timeout

Проверьте:

1. MySQL запущена;
2. используется внутреннее доменное имя MySQL;
3. перед именем хоста нет https://;
4. порт равен 3306;
5. API и MySQL доступны друг другу в Amvera.

### Ошибка разбора DATABASE_URL

Удалите пробелы и внешние кавычки. Если пароль содержит специальные символы, примените URL-кодирование или создайте новый длинный пароль из букв и цифр.

### Telegram: кнопка «Сайт» не открывается

Проверьте **SITE_URL** в Amvera. Там должен быть ровно один полный HTTPS-адрес без запятой, например:

~~~text
https://example.ru
~~~

Нельзя указывать `https://example.ru,https://www.example.ru`: Telegram считает это некорректным URL. Если сайт нужен в вариантах с www и без www, оба адреса перечисляют только в **CORS_ORIGINS**. После исправления переменной пересоберите приложение, чтобы бот получил новое значение.

### Ошибка 502

Проверьте:

- containerPort равен 5000;
- PORT равен 5000;
- публичный домен направлен на порт 5000;
- в логе есть запуск Gunicorn на 0.0.0.0:5000.
