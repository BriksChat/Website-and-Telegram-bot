# REG.RU: сайт и админ-панель

Начинайте этот этап только после того, как публичные адреса **/api/health** и **/api/all-words** в Amvera работают без ошибок.

Результат этапа — полностью рабочий сайт на собственном домене, подключённый через API к MySQL. Telegram-бот для этого не требуется.

## Архитектура

~~~text
Браузер → сайт на REG.RU → HTTPS API в Amvera → MySQL в Amvera
~~~

Браузер никогда не получает DATABASE_URL или пароль MySQL.

## 1. Подготовьте домен и хостинг

1. Купите домен и обычный хостинг сайта на REG.RU.
2. Добавьте домен в панели хостинга.
3. Направьте домен на этот хостинг по инструкции REG.RU.
4. Дождитесь, когда по домену начнёт открываться страница хостинга.
5. Включите бесплатный SSL-сертификат.
6. Проверьте, что адрес сайта начинается с **https://**.

Сохраните основной адрес, например:

~~~text
https://example.ru
~~~

Если используется адрес с www, сохраните и его:

~~~text
https://www.example.ru
~~~

## 2. Укажите адрес API в website/config.js

Откройте в своей копии GitHub файл **website/config.js** и нажмите кнопку редактирования.

На этапе REG.RU файл должен выглядеть так:

~~~javascript
window.ENGLISH_API_URL = 'https://ВАШ-API.amvera.io';
window.TELEGRAM_BOT_URL = '';
~~~

Правила:

- используйте настоящий публичный HTTPS-адрес API Amvera;
- не добавляйте **/api** в конец;
- не оставляйте завершающий слеш;
- TELEGRAM_BOT_URL оставьте пустым до этапа создания бота;
- не добавляйте пароли и токены.

Сохраните изменение в своей ветке main.

## 3. Разрешите домену обращаться к API

В приложении API в Amvera создайте или измените обычные переменные:

| Название | Значение |
|---|---|
| **SITE_URL** | https://example.ru |
| **CORS_ORIGINS** | https://example.ru |

Если сайт доступен с www и без www:

~~~text
https://example.ru,https://www.example.ru
~~~

В CORS_ORIGINS нельзя ставить слеш в конце адреса.

После изменения переменных перезапустите приложение API.

## 4. Загрузите сайт на REG.RU

1. Скачайте ZIP своей копии репозитория из GitHub.
2. Распакуйте архив.
3. Откройте папку **website**.
4. Выделите всё содержимое этой папки.
5. Загрузите файлы в корневую папку домена на хостинге REG.RU.

Нужно загружать содержимое папки **website**, а не создавать лишний уровень **website/website**.

В корне сайта должны находиться как минимум:

~~~text
index.html
admin.html
config.js
script.js
style.css
images/
~~~

Если панель REG.RU умеет распаковывать ZIP, создайте архив именно из содержимого **website** и распакуйте его в корень сайта.

## 5. Проверьте обычный сайт

Откройте домен в приватном окне браузера.

Проверьте:

1. сайт загружается по HTTPS;
2. появляется первая карточка;
3. можно собрать пару слов;
4. статистика меняется;
5. открывается общий словарь;
6. можно добавить слово в личный словарь;
7. после обновления страницы прогресс остаётся;
8. кнопка Telegram пока не показывается.

Если вместо карточек появляется ошибка API, смотрите раздел «Частые ошибки» ниже.

## 6. Откройте админ-панель

Админ-панель уже находится в файле **website/admin.html**. Отдельно создавать или собирать её не нужно.

Откройте:

~~~text
https://ВАШ-ДОМЕН/admin.html
~~~

Введите значение **ADMIN_PASSWORD**, которое было сохранено как секрет приложения API в Amvera.

Пароль вводится только в форму админ-панели. Его нельзя записывать в **config.js**, HTML или другие файлы сайта.

## 7. Проверьте редактирование словаря

В админ-панели:

1. войдите с ADMIN_PASSWORD;
2. найдите тестовое слово;
3. измените его перевод;
4. откройте общий словарь на обычном сайте и убедитесь, что изменение появилось;
5. добавьте новое тестовое слово;
6. убедитесь, что оно появилось на сайте;
7. удалите только созданное тестовое слово;
8. перезапустите приложение API в Amvera;
9. снова откройте словарь и убедитесь, что остальные изменения сохранились.

Сохранение после перезапуска подтверждает, что сайт действительно работает с MySQL, а не с временной SQLite.

## Частые ошибки

### Сайт открывается, но карточки не загружаются

Проверьте **website/config.js** на сервере. ENGLISH_API_URL должен содержать публичный HTTPS-адрес API без **/api** и без слеша в конце.

После замены config.js обновите страницу сочетанием Ctrl+F5 или откройте приватное окно.

### Ошибка CORS

Проверьте CORS_ORIGINS в Amvera. Адрес должен в точности совпадать с адресом в строке браузера:

- http и https считаются разными;
- www и адрес без www считаются разными;
- лишний слеш в конце мешает совпадению.

После изменения перезапустите API.

### Mixed Content или заблокированный запрос

Сайт и API должны использовать HTTPS. Нельзя подключать HTTPS-сайт REG.RU к локальному адресу **http://127.0.0.1:5000**.

### 404 для admin.html или файлов оформления

Файлы загружены не в корень домена или появилась лишняя папка **website**. Переместите содержимое **website** непосредственно в корневую папку сайта.

### Админ-панель отвечает «ADMIN_PASSWORD не настроен»

Создайте секрет ADMIN_PASSWORD в приложении API Amvera и перезапустите приложение.

### Админ-панель отвечает «Неверный пароль»

Введите точное значение секрета ADMIN_PASSWORD. Пароль MySQL и пароль админ-панели — разные значения.
